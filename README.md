# workspace-setup


Персональные конфигурационные файлы (dotfiles) и рабочее окружение для Linux (Fedora Workstation).

Управление симлинками и структурой каталогов реализовано через **GNU Stow**. Конфигурации хранятся в репозитории и связываются с домашней директорией без ручного копирования.

---

## Стек инструментов

* **Терминал:** [Kitty](https://sw.kovidgoyal.net/kitty/) (поддержка тем, лигатуры, GPU-рендеринг)
* **Shell:** [Zsh](https://www.zsh.org/) (алиасы, интеграция утилит)
* **Мультиплексор:** [tmux](https://github.com/tmux/tmux) (сессии, сплиты, навигация)
* **Симлинки:** [GNU Stow](https://www.gnu.org/software/stow/)

---

## Развёртывание на новой системе

### 1. Установка базовых пакетов (Fedora)

```bash
sudo dnf install -y git stow zsh tmux kitty

```

### 2. Клонирование репозитория

```bash
mkdir -p ~/projects
cd ~/projects
git clone git@github.com:Fil98/workspace-setup.git
cd workspace-setup

```

### 3. Создание символических ссылок

Перед развёртыванием создайте резервные копии дефолтных файлов, если они уже существуют в `$HOME` (например, `~/.zshrc`), после чего примените пакеты:

```bash
# Применение всех пакетов сразу
stow -t ~ zsh tmux kitty

```

Если потребуется отключить или перелинковать конкретный пакет:

```bash
# Отключение пакета
stow -D -t ~ tmux

# Повторная линковка
stow -R -t ~ tmux

```

## Рабочий процесс (Workflow)

Поскольку файлы в `$HOME` являются символическими ссылками на этот репозиторий:

1. Редактировать конфиги можно как напрямую по стандартным путям (`~/.zshrc`, `~/.config/kitty/kitty.conf`), так и внутри репозитория.
2. Проверить изменения перед коммитом:
```bash
cd ~/projects/workspace-setup
git status
git diff

```


3. Зафиксировать и отправить изменения:
```bash
git add .
git commit -m "feat(tmux): update keybindings"
git push origin main

```

## Безопасность

* Чувствительные данные (токены доступа, API-ключи, приватные сертификаты и конфигурации рабочих кластеров) исключены через `.gitignore`.
* Локальные переопределения и приватные переменные окружения рекомендуется выносить в неверсионируемые файлы вроде `~/.zshrc.local` (подключаемые через проверку `[ -f ~/.zshrc.local ] && source ~/.zshrc.local`).
